# プライバシーに関する説明

English: [Privacy](/security/privacy)

Kurahiは自社ホスト型です。利用者のマシン上で動作し、利用者が管理する1つのディレクトリにデータを保存し、利用者が設定した宛先にだけデータを送ります。このページはその全リストです。

## マシンの外に出るデータと、その止め方

| 通信                         | 内容                                                  | 宛先                                        | 既定で有効                             | 無効化                                                                           |
| ---------------------------- | ----------------------------------------------------- | ------------------------------------------- | -------------------------------------- | -------------------------------------------------------------------------------- |
| モデルへのリクエスト         | 会話（プロンプト、ツール結果）とエージェントへの指示  | 設定したモデルプロバイダー                  | プロバイダーを選ぶまで無効             | `local` プロファイル（このマシン上のモデルサーバー）を選ぶか、プロバイダーを削除 |
| メッセージングチャネル       | そのチャネルでやり取りするメッセージ                  | 各チャネルのサービス（LINE、Telegramなど） | 無効                                   | チャネルを有効化しない                                                           |
| 更新確認                     | バージョン情報のみ（HTTPリクエスト以上の識別子なし） | パッケージレジストリ                        | npmインストールではゲートウェイ起動時 | `update.checkOnStart: false`                                                     |
| ローカルネットワークへの告知 | mDNS/Bonjourによるゲートウェイ名                     | 同一LAN                                    | minimal                                | `gateway.discovery.mdns.mode: "off"`                                             |
| インストーラー               | リリースバンドルとチェックサムのダウンロード          | github.com                                  | インストール時のみ                     | オフラインインストール（`--bundle`）                                             |

テレメトリー、アナリティクス、クラッシュレポート、利用統計、提供元への自動通信はありません。Kurahiは実行時に提供元へ何も送信しません。サポートバンドル（`kurahi support`）はローカルに書き出され、利用者がチケットに添付したときだけ送られます。

すべての外向き通信を止めた設定例:

```json5
{
  update: { checkOnStart: false },
  gateway: { bind: "loopback", discovery: { mdns: { mode: "off" } } },
  agents: { defaults: { model: { primary: "ollama/<ローカルモデル>" } } },
}
```

## 保存されるデータ、場所、期間

すべて `KOLO_HOME`（`~/.kolo`、Windowsは `%LOCALAPPDATA%\KoLo`）配下にあり、サービスユーザーが所有します。

| データ                                             | パス                                              | 保持                                             | 個人データを含むか                     |
| -------------------------------------------------- | ------------------------------------------------- | ------------------------------------------------ | -------------------------------------- |
| 設定                                               | `kolo.json`                                       | 変更まで                                         | 入力した名前や識別子                   |
| ゲートウェイトークン、シークレット、端末の資格情報 | `secrets/`（権限0600。資格情報はハッシュで保存） | 取り消しまたは削除まで                           | いいえ                                 |
| 会話                                               | `agents/<id>/sessions/`                           | 削除するまで。アップロードなし                   | はい（入力した内容）                   |
| 作業領域とメモリ                                   | `workspace/`                                      | 削除まで                                         | エージェントが保存した場合はあり得る   |
| ログ                                               | `logs/`                                           | 日次ファイル。自由に削除可。シークレットはマスク | 既定ではメッセージのメタデータのみ     |
| 監査チェーン                                       | `audit/`                                          | 月次ファイル。ポリシーに従って保管               | 識別名と操作。メッセージ本文は含まない |
| サポートバンドル                                   | `support/`                                        | `kurahi support` 実行時のみ                      | マスク済みの設定とログ末尾             |

モデルプロバイダーとチャネル事業者は、それぞれの規約に基づいて独自にデータを保持します。規制対象データを送る前に各社の規約を確認してください。

## アクセス

- `KOLO_HOME` を読めるのはサービスユーザーだけです。シークレットは0600です。
- 死活確認（`/health`: 状態、バージョン、稼働時間）を除き、すべてのネットワークルートは資格情報を要求します。
- ペアリングした端末には、スコープ付きで取り消し可能な資格情報が発行されます。`kurahi pair list` で一覧、`kurahi pair revoke <id>` で取り消しです。
- すべてのアクセスは監査チェーンに記録されます（`kurahi audit tail`）。

## データの削除

- 特定の会話：ゲートウェイを停止した状態で `agents/<id>/sessions/` 配下のファイルを削除します。`kurahi sessions` で対象を探せます。
- すべて：`kurahi uninstall --all --yes` が `KOLO_HOME` と作業領域を削除します。プログラム本体はインストール先を削除してください。`--dry-run` で事前に一覧を確認できます。
- ペアリング済み端末：取り消しの監査記録を残したい場合は、完全削除の前に取り消してください。完全削除後はいずれにせよトークンは無効になります。
